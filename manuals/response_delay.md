# MQTT 요청·응답 지연 점검

장애 유형: RESPONSE_DELAY

## 판정과 범위
규칙 엔진은 요청의 `request_id`와 일치하는 응답이 3초를 넘어서 도착하거나 3초 내 응답하지 않으면 관련 장애를 기록한다. 지연 기록만으로 장치 부하나 네트워크 문제를 확정할 수 없다.

## 가능한 원인
장치의 요청 처리 지연, 장치 CPU 부하, MQTT 재연결, 네트워크 지연, 응답 topic 또는 `request_id` 불일치가 가능하다. 해당 요청과 응답의 원본 로그를 대조해야 한다.

## 점검 순서
1. 요청 시각, 응답 시각, `request_id` 및 `factory/RPI-01/request`, `factory/RPI-01/response` topic을 비교한다.
2. 응답이 도착했는지, 늦게 도착했는지, 아예 없는지 구분한다.
3. 장치 처리 시간과 CPU 상태, 브로커 연결 및 네트워크 지연을 확인한다.
4. 동일 조건에서 요청을 재실행해 지연이 반복되는지 기록한다.

## 추가 확인
상태 메시지가 정상이어도 요청 처리 경로만 느릴 수 있다. 응답이 없는 경우에는 처리 지연과 구독 누락을 구분해야 한다. 조치 후 실제 요청·응답 시간을 재측정한다.
