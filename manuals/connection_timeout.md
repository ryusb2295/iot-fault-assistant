# MQTT 상태 메시지 미수신 점검

장애 유형: CONNECTION_TIMEOUT

## 판정과 범위
규칙 엔진은 유효한 상태 메시지를 받은 뒤 10초 동안 다음 상태 메시지를 받지 못하면 CONNECTION_TIMEOUT을 기록한다. 이 기록만으로 장치 전원, 네트워크 또는 브로커 중 어느 곳이 원인인지 확정할 수 없다.

## 가능한 원인
장치 발행 프로세스 중단, 장치와 브로커 사이의 네트워크 단절, MQTT 브로커 중단, 잘못된 브로커 주소나 포트, 상태 topic 불일치가 가능한 원인이다. 로그와 현장 상태로 각각 확인해야 한다.

## 점검 순서
1. 장애 발생 시각과 마지막 유효 상태 메시지 시각을 비교한다.
2. Mosquitto 실행 상태와 `MQTT_HOST`, `MQTT_PORT` 접속 값을 확인한다.
3. `factory/RPI-01/status` 발행 및 구독 상태와 장치 네트워크 연결을 확인한다.
4. 장치 발행 프로세스와 전원을 확인한 뒤 상태 메시지 재수신 여부를 관찰한다.

## 추가 확인
요청·응답 메시지가 계속 오는데 상태 메시지만 없다면 상태 발행 경로와 topic을 우선 확인한다. 모든 MQTT 메시지가 없다면 브로커와 네트워크를 함께 점검한다. 복구 여부는 실제 메시지 수신 기록으로 판단한다.
