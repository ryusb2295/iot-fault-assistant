# 발표 시연 준비와 녹화 순서

## 발표용 DB 분리

개발 DB `backend/iot_faults.sqlite3`에는 기존 테스트 이력이 있다. 발표에는 새 파일을 사용한다. 기존 발표 DB도 덮어쓰지 않는다.

```powershell
python scripts/prepare_presentation_db.py --output backend/iot_presentation_20261106.sqlite3
$env:IOT_DB_PATH = (Resolve-Path backend/iot_presentation_20261106.sqlite3).Path
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

다른 PowerShell 창에서 MQTT Worker를 시작할 때 **같은** `IOT_DB_PATH`를 설정한다. 브로커와 시뮬레이터 실행 방식은 `README.md` 및 `RASPBERRY_PI_SETUP.md`를 따른다. DB 파일은 Git에서 제외된다. 새 시연을 반복할 때는 새 파일명을 사용한다.

## 사전 확인

1. 브로커, FastAPI, Worker, Ollama의 상태를 확인한다.
2. `/api/health`가 응답하는지 확인한다.
3. 발표용 DB의 장애 건수가 0인지 확인한다.
4. 정상 모드에서 RPI-01의 마지막 수신 시각이 갱신되는지 확인한다.
5. 장애 모드와 정상 복귀를 한 번 연습하고 실제 발표 전에는 새 발표 DB로 다시 시작한다.

| 구간 | 화면 | 확인할 사실 |

실제 작동 화면 녹화는 `presentation/video/mqtt_fault_demo_2026-11-06T13-53-32-334Z.webm`에 있다. 격리된 발표 DB와 포트 1884/8001/5175를 사용했고, 녹화용 DB에 장애 이벤트 5건과 통신 로그 37건이 기록됐다. 영상에서는 정상 수신, 지연 모드 전환, 장애 이력·상세, 정상 복귀를 확인한다.
