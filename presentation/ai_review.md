# 실제 AI 점검 안내 검토

검토 대상: 발표용 분리 DB `backend/iot_presentation_clean.sqlite3`의 응답 지연 이벤트 ID 2. 로컬 Ollama `exaone3.5:2.4b`를 새로 호출했다. 원본 응답과 검색 출처는 `ai_review_sample.json`에 저장했다. 기존 CSV의 AI 5회 호출과는 별개의 재검증이다.

## 확인 결과

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 장애 유형과 문서 일치 | 적합 | `RESPONSE_DELAY`에 `manuals/response_delay.md`의 네 절이 검색됨 |
| 매뉴얼에 있는 원인 후보 | 대체로 적합 | 처리 지연, CPU 부하, MQTT 재연결, 네트워크 지연, topic·request_id 불일치를 가능성으로 표현 |
| 로그에 없는 시각 단정 | 개선 | 프롬프트 수정 후 ‘마지막 정상 응답 시각’ 단정은 재검증 응답에 없음 |
| 매뉴얼 밖의 원인·점검 | 부적합 | ‘소프트웨어 버그’, ‘소프트웨어 업데이트 확인’, ‘다른 네트워크 환경에서 재시도’는 검색 문서와 연결 로그에 없음 |

**판정: 부분 적합.** 생성 성공과 출처 표시만으로 답변 전체가 근거에 충실하다고 말할 수 없다. 프롬프트에 매뉴얼 밖 권고를 금지하는 문구를 추가했지만 재검증에서도 위 항목이 남았다. 발표에서는 이 한계를 명시하고, AI 안내를 확정 진단이나 자동 조치로 소개하지 않는다. 다음 개선은 문장별 출처 대조와 근거 밖 문장 차단이다.

기존 AI 5회의 답변 본문은 저장돼 있지 않다. 따라서 이 검토를 5회 전체 평가로 환산하지 않는다.
